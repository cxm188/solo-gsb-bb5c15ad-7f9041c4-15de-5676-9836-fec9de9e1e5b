# 字幕断句(Subtitle Segmenter)

基于 FastAPI + 原生 HTML/JavaScript 的字幕断句网页应用。用户粘贴带时间戳的词序列,可标记不可拆短语、按词间隙设置边界约束;系统在「每条最多两行、行宽与阅读速度限制」下,用全局动态规划选择分段,使 **镜头切点偏差 + 行长不均 + 不自然停顿** 的加权总代价最低。页面实时展示断句预览与逐段代价,调整权重或边界约束即时重算;无可行方案时定位首个冲突区间(或首个不可行边界)及具体原因并高亮。请求 `alternatives`(1～5,默认 1)大于 1 时,后端用 **K-best 动态规划** 返回总代价从低到高的备选方案,可在页面切换并突出与最优方案不同的断点。

## 启动

```bash
docker compose up --build
```

依赖安装与应用初始化均随容器启动自动完成,无需本地环境。

## 访问

- 网页界面: http://localhost:8000
- API: `POST http://localhost:8000/api/segment`

## 边界约束

在「词序列 · 边界约束」面板中,点击两个词之间的间隙即可设置硬约束,再次点击循环切换,第三次点击清除:

| 标记 | 类型 | 含义 |
| --- | --- | --- |
| 红色竖线 | `must_break` | 必须断开:分段边界必须落在该间隙 |
| 绿色横线 | `no_break` | 禁止断开:间隙两侧的词必须落在同一段 |
| 紫色细线 | (不可设置) | 不可拆短语内部的间隙,不允许设置边界 |

约束随请求提交,在全局动态规划中作为硬条件生效。若约束导致无可行方案(例如必须断开后任一侧违反时长、行宽或阅读速度限制),响应返回**首个不可行边界**及具体原因,页面保留输入与标记,并高亮冲突边界与冲突词区间;调整约束或权重后即时重算。

## 配置

无需环境变量;所有参数在网页左侧面板调整(也可通过 API 的 `config` 字段传入):

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `max_chars_per_line` | 42 | 单行最大字符数(硬约束,每段最多 2 行) |
| `max_cps` | 20 | 最大阅读速度,字/秒(硬约束) |
| `min_duration` | 0.8 | 每段最短时长,秒(硬约束) |
| `max_duration` | 7.0 | 每段最长时长,秒(硬约束) |
| `pause_threshold` | 0.3 | 词间间隔小于该值视为不自然断点,秒 |
| `shot_dev_cap` | 0.5 | 镜头切点偏差归一化上限,秒 |
| `crossing_penalty` | 1.0 | 分段跨越一个镜头切点的惩罚 |
| `w_shot` | 1.0 | 权重:镜头切点偏差 |
| `w_imbalance` | 1.0 | 权重:行长不均 |
| `w_pause` | 1.0 | 权重:不自然停顿 |

## 输入格式

- **词序列**:每行 `开始 结束 文本`,时间支持 `HH:MM:SS.mmm` 或秒数;也接受 JSON 数组 `[{"text","start","end"}]`。
- **不可拆短语**:每行一个,词下标区间(如 `3-6`,含端点)或短语原文(自动匹配首个连续出现)。
- **边界约束**:在词序列预览中点击词间间隙设置(见上节);约束按词间隙下标解释,修改词序列后请核对位置。
- **镜头切点**:每行一个时间点。

## API

`POST /api/segment`,请求体:

```json
{
  "words": [{"text": "我们", "start": 0.5, "end": 0.9}],
  "phrases": [[4, 5, 6]],
  "shots": [4.5, 8.0],
  "boundaries": [{"index": 7, "type": "must_break"}, {"index": 10, "type": "no_break"}],
  "alternatives": 3,
  "config": {"max_cps": 20, "w_shot": 1.0}
}
```

- `words`(必填):词序列,含 `text` / `start` / `end`(秒)。
- `phrases`(可选,默认 `[]`):不可拆短语的词下标区间(连续、含端点)。
- `shots`(可选,默认 `[]`):镜头切点时间(秒)。
- `boundaries`(可选,默认 `[]`):词间隙边界约束。`index = k` 表示词 `k-1` 与词 `k` 之间的间隙(`1 <= k <= len(words)-1`);`type` 为 `must_break`(必须断开)或 `no_break`(禁止断开)。同一间隙不得同时设置两种类型;间隙不得位于不可拆短语内部,否则返回 422。**不传该字段时行为与旧版完全一致。**
- `alternatives`(可选,默认 `1`,取值 1～5):请求的备选方案数。全部硬约束(行宽、行数、阅读速度、时长、不可拆短语)与边界约束(`must_break` / `no_break`)对所有方案一视同仁;后端在分段 DAG 上做 K-best 动态规划,按**分段边界序列判重**,返回总代价从低到高的互不重复方案。不足 `alternatives` 个时返回实际数量(最少 1 个,即至少有一个可行方案时)。
- `config`(可选):见「配置」表,未传字段取默认值。

响应:

- 可行:`{"ok": true, "total_cost": ..., "segments": [...]}`;当且仅当 `alternatives > 1` 时额外含 `alternatives` 数组,第 0 项即顶层最优方案(`cost_delta` 为 0):
  ```json
  {"ok": true, "total_cost": 2.6667, "segments": [...],
   "alternatives": [
     {"segments": [...], "total_cost": 2.6667, "cost_delta": 0.0},
     {"segments": [...], "total_cost": 2.7, "cost_delta": 0.0333}
   ]}
  ```
  每项含 `segments`(结构与顶层 `segments` 相同)、`total_cost`(总代价)和 `cost_delta`(与最优方案的总代价之差,按未取整代价计算后四舍五入到 4 位小数,故可能与取整后两项之差相差 0.0001);顶层 `total_cost` / `segments` 始终代表最优方案,因此不传 `alternatives` 或传 1 时响应与旧版完全一致。
- 不可行:`{"ok": false, "conflict": {...}}`(不含 `alternatives`),`conflict` 含冲突区间 `word_range` / `start` / `end` / `text` / `reasons`(具体违例,如「时长 0.30s 低于下限 0.8s」);若不可行由边界约束导致,另含 `boundary: {"index", "type"}`,即首个不可行边界。

## 备选方案(页面)

在「约束与权重」面板把**备选方案数量**设为大于 1 后,断句预览顶部出现方案切换条:`最优方案` 与 `方案 2…N`,非最优按钮标注相对代价增量(如 `+0.0333`)。切换后:

- 预览分段、逐段代价与总代价随所选方案更新;
- 词序列中用蓝色竖线标出当前方案断点,与最优方案不同的断点用**橙色**加粗竖线;最优方案有、当前方案没有的断点用蓝色空心圆标出(用户手动设置的必须断开 / 禁止断开标记不被覆盖);
- 段首断点与最优方案不同的分段以橙色描边并标注「断点不同于最优」;
- 只有一个可行方案时显示「只有一个可行方案,无更多备选」。
